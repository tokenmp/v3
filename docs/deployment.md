# Fresh-server deployment

This runbook makes a new **HTTPS** deployment from a clean clone. It is an operator procedure, not a record of any existing server. Substitute environment-owned DNS names, paths, database credentials, provider identifiers, and secret values; do not commit those values or the files below. The Compose project is always `tokenmp-v3`.

> [!WARNING]
> Confirm the target environment, database ownership, backup policy, Compose working directory, image tag, and external PostgreSQL/Redis reachability before running migrations or `up`. This runbook does not authorize production deployment, destructive SQL, volume deletion, or `docker compose down -v`.

## 1. Prerequisites

Install Docker Engine with the Compose plugin, `git`, `openssl`, `curl`, `jq`, and the [golang-migrate CLI](https://github.com/golang-migrate/migrate). The server needs no host Node, pnpm, or Go to build/run Compose images, but `migrate` is deliberately run outside containers.

Provision **external, backed-up** PostgreSQL and Redis. Create these five PostgreSQL databases, granting the deployment principal only the required access:

| Database | Service migration directory | DSN environment variable |
|---|---|---|
| `tokenmp_auth` | `services/auth/migrations` | `AUTH_DATABASE_URL` |
| `tokenmp_config` | `services/config/migrations` | `CONFIG_DATABASE_URL` |
| `tokenmp_logging` | `services/logging/migrations` | `LOGGING_DATABASE_URL` |
| `tokenmp_billing` | `services/billing/migrations` | `BILLING_DATABASE_URL` |
| `tokenmp_biz` | `services/notice/migrations` | `NOTICE_DATABASE_URL` |

All DSNs are service-validated to their database path. Do not reuse a database for a different service. Redis is external; its reachable URL is `TOKENMP_V3_EXTERNAL_REDIS_ADDR`.

Clone a reviewed release/ref and create an operator-owned, gitignored deployment directory for secrets and environment files:

```bash
git clone <repository-url> tokenmp-v3
cd tokenmp-v3
git checkout <reviewed-tag-or-commit>
DEPLOY_SECRETS_DIR=<deployment-owned-secret-directory>
install -d -m 0700 "$DEPLOY_SECRETS_DIR"
```

## 2. Generate JWT keys and internal secret files

Generate the Ed25519 pair once in the protected deployment directory:

```bash
tools/generate-jwt-keys.sh $DEPLOY_SECRETS_DIR
```

`auth-jwt-private.pem` is mounted only into Auth. Mount the same `auth-jwt-public.pem` read-only into API, Executor, and Notice; a mismatched public key causes authentication failures. Do not regenerate a live key pair without a coordinated token-rotation plan. The helper requires `openssl` with Ed25519 support and refuses to overwrite existing key files.

Create the remaining random tokens without displaying them. The following commands write values to local files only:

```bash
umask 077
for name in auth-rate-limit-hmac api-rate-limit-hmac config-admin-token \
  api-config-service-token billing-logging-service-token; do
  openssl rand -base64 48 > "$DEPLOY_SECRETS_DIR/${name}"
done
chmod 0600 $DEPLOY_SECRETS_DIR/{auth-rate-limit-hmac,api-rate-limit-hmac,config-admin-token,api-config-service-token,billing-logging-service-token}
```

| File | Compose input variable | Purpose / generation |
|---|---|---|
| `auth-jwt-private.pem` | `AUTH_JWT_PRIVATE_KEY_FILE` | Auth signing key; generated by `tools/generate-jwt-keys.sh`; mode `0600` |
| `auth-jwt-public.pem` | `AUTH_JWT_PUBLIC_KEY_FILE`, `API_JWT_PUBLIC_KEY_FILE`, `EXECUTOR_JWT_PUBLIC_KEY_FILE`, `NOTICE_JWT_PUBLIC_KEY_FILE` | JWT verification key; generated by the same script; mode `0644` |
| `auth-rate-limit-hmac` | `TOKENMP_V3_AUTH_RATE_LIMIT_HMAC_SECRET_FILE` | Auth Redis-key HMAC; `openssl rand -base64 48`; mode `0600` |
| `api-rate-limit-hmac` | `TOKENMP_V3_API_RATE_LIMIT_HMAC_SECRET_FILE` | API Redis-key HMAC; same generation; mode `0600` |
| `config-admin-token` | `TOKENMP_V3_CONFIG_ADMIN_TOKEN_FILE` | Config admin API bearer token; same generation; mode `0600` |
| `api-config-service-token` | `TOKENMP_V3_API_CONFIG_SERVICE_TOKEN_FILE` | API-to-Config admin bearer token; it must contain the **same value** as `config-admin-token`; use a protected copy, not a printed value |
| `billing-logging-service-token` | `TOKENMP_V3_BILLING_LOGGING_SERVICE_TOKEN_FILE` | Billing-to-Logging bearer token; same generation; mode `0600` |
| `executor-credentials.env` | `TOKENMP_V3_EXECUTOR_CREDENTIAL_ENV_FILE` | deployment-owned `EXECUTOR_CREDENTIAL_*` values; see [credential mapping](#7-executor-credential-mapping) |

Copy the Config token locally without echoing it:

```bash
cp $DEPLOY_SECRETS_DIR/config-admin-token $DEPLOY_SECRETS_DIR/api-config-service-token
chmod 0600 $DEPLOY_SECRETS_DIR/api-config-service-token
```

## 3. Prepare the Compose environment

Create a mode-`0600` env file outside the repository (or otherwise ensure it is ignored). All `:?required` entries from [`compose.yaml`](../compose.yaml) must be set. This safe-shape example deliberately uses placeholders, not credentials:

```dotenv
TOKENMP_V3_IMAGE_TAG=<reviewed-image-tag>
AUTH_DATABASE_URL=postgres://<user>:<password>@<postgres-host>:5432/tokenmp_auth?sslmode=require
CONFIG_DATABASE_URL=postgres://<user>:<password>@<postgres-host>:5432/tokenmp_config?sslmode=require
LOGGING_DATABASE_URL=postgres://<user>:<password>@<postgres-host>:5432/tokenmp_logging?sslmode=require
BILLING_DATABASE_URL=postgres://<user>:<password>@<postgres-host>:5432/tokenmp_billing?sslmode=require
NOTICE_DATABASE_URL=postgres://<user>:<password>@<postgres-host>:5432/tokenmp_biz?sslmode=require
TOKENMP_V3_EXTERNAL_REDIS_ADDR=rediss://<redis-host>:6379/0
AUTH_RATE_LIMIT_TRUSTED_PROXIES=<reverse-proxy-CIDR>
API_RATE_LIMIT_TRUSTED_PROXIES=<reverse-proxy-CIDR>
AUTH_JWT_PRIVATE_KEY_FILE=<deployment-owned-secret-directory>/auth-jwt-private.pem
AUTH_JWT_PUBLIC_KEY_FILE=<deployment-owned-secret-directory>/auth-jwt-public.pem
API_JWT_PUBLIC_KEY_FILE=<deployment-owned-secret-directory>/auth-jwt-public.pem
EXECUTOR_JWT_PUBLIC_KEY_FILE=<deployment-owned-secret-directory>/auth-jwt-public.pem
NOTICE_JWT_PUBLIC_KEY_FILE=<deployment-owned-secret-directory>/auth-jwt-public.pem
TOKENMP_V3_AUTH_RATE_LIMIT_HMAC_SECRET_FILE=<deployment-owned-secret-directory>/auth-rate-limit-hmac
TOKENMP_V3_API_RATE_LIMIT_HMAC_SECRET_FILE=<deployment-owned-secret-directory>/api-rate-limit-hmac
TOKENMP_V3_CONFIG_ADMIN_TOKEN_FILE=<deployment-owned-secret-directory>/config-admin-token
TOKENMP_V3_API_CONFIG_SERVICE_TOKEN_FILE=<deployment-owned-secret-directory>/api-config-service-token
TOKENMP_V3_BILLING_LOGGING_SERVICE_TOKEN_FILE=<deployment-owned-secret-directory>/billing-logging-service-token
TOKENMP_V3_EXECUTOR_CREDENTIAL_ENV_FILE=<deployment-owned-secret-directory>/executor-credentials.env
EXECUTOR_CREDENTIAL_REF_MAP_JSON={"vault://<provider-id>/credential/default":"EXECUTOR_CREDENTIAL_<PROVIDER>_DEFAULT"}
API_EXECUTOR_TOKEN= # leave empty for the default JWT-passthrough mode
```

Optional Compose inputs have safe defaults: `AUTH_API_BASE=http://auth:8080`, `API_EXECUTOR_TOKEN` is empty for JWT passthrough, rate-limit enabled flags default false, image tag defaults `latest`, and Web public base URLs/mocks default to same-origin/`0`. `AUTH_API_BASE` is a **runtime server-side** Web setting; it must remain an Auth-reachable URL, not the browser's BFF URL. `NEXT_PUBLIC_*` values are public build arguments and are immutable after image build—never put secrets in them. Set `TOKENMP_V3_API_HOST_PORT` / `TOKENMP_V3_WEB_HOST_PORT` only if the host ports need overriding.

Render before any start; it checks required input completeness without starting a service. Compose expands `env_file` values in its output, so protect or redact the output and never upload it to CI/logs:

```bash
docker compose --env-file $DEPLOY_SECRETS_DIR/compose.env -p tokenmp-v3 config >/dev/null
```

## 4. Apply migrations

Take/verify backups according to the database owner policy before a rollback or any destructive action. For a new, empty database, run only `up` for each exact target DSN:

```bash
migrate -path services/auth/migrations    -database "$AUTH_DATABASE_URL" up
migrate -path services/config/migrations  -database "$CONFIG_DATABASE_URL" up
migrate -path services/logging/migrations -database "$LOGGING_DATABASE_URL" up
migrate -path services/billing/migrations -database "$BILLING_DATABASE_URL" up
migrate -path services/notice/migrations  -database "$NOTICE_DATABASE_URL" up
```

Export these local shell variables from the protected env file only in a controlled operator shell; never paste DSNs into tickets or logs. Do **not** use `down` as routine cleanup. Existing data and fail-closed down migrations require a separate approved rollback plan.

## 5. Seed and publish initial Config

Executor requires a published Config snapshot. Copy [`tools/seed-config.example.json`](../tools/seed-config.example.json) outside the repository, replace every `replace-with-...` placeholder with one real provider/model/route, use an actual HTTPS provider `base_url`, and retain a `vault://` `credential_ref`. The example contains no provider secret.

Start Config alone after migrations, using the same protected env file, and wait for its readiness endpoint through its loopback-only port. Then seed through the protected Config admin API:

```bash
docker compose --env-file $DEPLOY_SECRETS_DIR/compose.env -p tokenmp-v3 up -d config
CONFIG_ADMIN_TOKEN_FILE=$DEPLOY_SECRETS_DIR/config-admin-token \
  tools/seed-config.sh http://127.0.0.1:<config-admin-port> $DEPLOY_SECRETS_DIR/seed-config.json
```

The script creates the provider/model/credential/route then calls `POST /v1/config/admin/compile`, which creates and publishes the initial raw snapshot. Do not expose the Config admin endpoint through the public proxy. Confirm it exists with `GET /v1/config/snapshots/latest` before starting Executor.

## 6. Build, start, and verify

After the seed and credential mapping are ready, build and start all application services:

```bash
docker compose --env-file $DEPLOY_SECRETS_DIR/compose.env -p tokenmp-v3 build
docker compose --env-file $DEPLOY_SECRETS_DIR/compose.env -p tokenmp-v3 up -d
docker compose --env-file $DEPLOY_SECRETS_DIR/compose.env -p tokenmp-v3 ps
```

Verify container health and public routing without logging tokens:

```bash
docker compose --env-file $DEPLOY_SECRETS_DIR/compose.env -p tokenmp-v3 ps
curl --fail --silent --show-error https://<public-host>/healthz
curl --fail --silent --show-error https://<public-host>/api/v1/plans
```

Finally perform a browser login over HTTPS and confirm the Web session cookie persists; this proves `/api/v1/auth/*` proxying and the `Secure` refresh-cookie requirement. With an authorized test account, request `/v1/models` and one configured model operation. A `401` from `/v1/models` proves only that the Edge route is reachable, not that authentication or the published Config snapshot works.

## 7. Executor credential mapping

`EXECUTOR_CREDENTIAL_REF_MAP_JSON` is a JSON object. Each key is exactly the `vault://` reference stored in Config DB `upstream_credentials.credential_ref`; each value is the **name** of a secret environment variable, not an API key and not a file path.

```json
{
  "vault://example-provider/credential/default": "EXECUTOR_CREDENTIAL_EXAMPLE_PROVIDER_DEFAULT"
}
```

The named environment variable is supplied only to the Executor through the protected `executor-credentials.env` file:

```dotenv
EXECUTOR_CREDENTIAL_EXAMPLE_PROVIDER_DEFAULT=<actual-upstream-api-key>
```

Keep this file mode `0600`, outside Git, and set `TOKENMP_V3_EXECUTOR_CREDENTIAL_ENV_FILE` to it. Never put the real API key in `seed-config.example.json`, Config DB, `EXECUTOR_CREDENTIAL_REF_MAP_JSON`, a Compose build argument, or public documentation. Every enabled Config credential ref must have one mapping entry; every mapping target must be an `EXECUTOR_CREDENTIAL_*` variable. Change the secret file and reload/recreate Executor according to the approved rotation procedure.

## 8. HTTPS reverse proxy

HTTPS is mandatory. Web sets refresh cookies with `Secure`; HTTP causes browsers to discard them. Terminate TLS at a separately managed Nginx/OpenResty proxy and forward only to the published API and Web host ports. Obtain a trusted certificate (for example with Let's Encrypt) or install a trusted internal CA certificate before user testing. A self-signed certificate is suitable only for controlled testing where clients explicitly trust that CA.

Example Nginx server block (replace certificate paths and upstream addresses; do not copy private environment topology into this repository):

```nginx
server {
    listen 443 ssl http2;
    server_name <public-host>;
    ssl_certificate     <certificate-fullchain-path>;
    ssl_certificate_key <certificate-private-key-path>;

    location /v1/ { proxy_pass http://127.0.0.1:3002; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto https; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
    location /api/v1/auth/ { proxy_pass http://127.0.0.1:8080; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto https; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
    location /api/v1/notice/ { proxy_pass http://127.0.0.1:<notice-host-port>; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto https; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
    location /api/v1/ { proxy_pass http://127.0.0.1:3002; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto https; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
    location /healthz { proxy_pass http://127.0.0.1:3002; }
    location / { proxy_pass http://127.0.0.1:3100; proxy_set_header Host $host; proxy_set_header X-Forwarded-Proto https; }
}
```

The proxy is external to Compose. Configure `AUTH_RATE_LIMIT_TRUSTED_PROXIES` and `API_RATE_LIMIT_TRUSTED_PROXIES` to the proxy CIDRs that actually connect to the containers; do not use an all-address CIDR.

## Rollback boundaries

Application rollback is an image-tag change only after compatibility and database migration review. Schema down is not an automatic rollback: confirm backups, target databases, and each service's migration constraints first. Do not remove shared PostgreSQL, Redis, proxy resources, or run `docker compose down -v` as part of rollback.
